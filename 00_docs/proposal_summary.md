# 方案摘要（源自 `E:\生成诗歌\第一版.pdf`）

> 本文件是项目唯一事实源。任何与 `第一版.pdf` 的不一致以本文件为准；本文件与 PDF 的不一致以 PDF 为准并修订本文件。

## 研究问题（第 1.1 节）

在中文诗歌中，是否存在可计算的文本特征，能够构成一个与人类在「诗歌/非诗歌」这个二分类问题上判断高度一致的自动「诗歌性」指标？如果存在，这种一致性在 AI 生成文本逐渐逼近人类诗歌的困难样本上，是否会衰减，如何衰减？衰减究竟表现为「指标先失效」，还是「人与指标同步失效」？

## 已知空白（第 1.1 节）

- 顶级 LLM 在形式准确性 / 主题对齐上表现尚可，但在创造力、独特性、情感共鸣、意象、文学手法运用上达不到人类诗人水平。
- BLEU / ROUGE 等以词面重叠为核心的指标不适合评测主题、情感、意象、形式、风格。
- LLM-as-a-Judge 在诗歌任务上系统性高估模仿统计模式的机器生成诗歌，且判断与人类专家评价明显偏离；同时也存在位置偏差、权威偏差、评分偏差等问题。

## 关键约束（第 2.1 节）

- 环境边界：Agent 只能用预先提供的数据集和基础评测特征。
- 稳定约束：Check-Agent 检查数据越界、规则绕过、协议修改；每轮前后边界检查，每 3 轮一次完整审计；越界结果标记为 INVALID。
- 不可修改规则：数据划分、测试集访问、人工评价标签、核心评价协议、实验目标。
- Agent 不得通过修改 Plan / 提示词 / Skills 绕过约束。

## 反馈机制（第 2.2 节）

- 性能反馈：每轮一致性值 vs. 预设阈值。
- 失败反馈：显著不一致样本记为反例，纳入负样本。
- 边界反馈：Check-Agent 越界审计。

## 发现信号（第 3.1 节）

- 第一阶段：正向发现 / 异常 / 反例 / 稳定负结果 / 失败模式。
- 第二阶段：相似度提升 + 检验「指标是否先于人类判断失效」。

## 三类参照（第 3.2 节）

- 平凡解参照：BLEU、ROUGE、单一基础特征。
- 随机参照：随机指标组合 / 随机分类。
- 无干预参照：固定初始方案，不做迭代。

## 试跑目标（第 4.1 节）

验证 AI4S 探索流程能跑通，不是为了得出科学结论。

## 资源预算（第 2.3 节）

- 计算：至少一块 A100 80G GPU。
- LLM：DeepSeek-V4-Flash 等 API，设总预算上限。
