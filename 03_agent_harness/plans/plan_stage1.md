# Plan · 第 1 阶段 · 指标组合探索（v2.0 迭代版）

> 不可由 Agent 修改。本文件由项目负责人维护。
> v2.0 更新（2026-08-14）：基于 13+ 轮实验的迭代闭环，Plan 现在明确支持**指标迭代**——发现失败模式 → 加特征或加反例 → 重训 → 验证。

## 目标

在 `02_environment/baseline_metrics/feature_catalog.md` 定义的特征库范围内，
寻找一个**与人类「诗歌/非诗歌」判断高度一致**的指标组合（特征集合 + 权重 + 聚合方式）。

**版本化目标**（取代一次性 kappa 阈值）：
- **v2（冻结）**：Kappa 0.940 on val，结构 / 语言 / 词重叠三族组合
- **v3**：+ purity 特征（无反例时无效）
- **v4b**：+ purity + 32 条 AI 垃圾负样本，Kappa 0.974 on val，AI 诗假阳性 0
- **v5**：+ style 特征（新闻词密度等），在 social/news 训练集上 recall 已达 1.0（v2 已解决）
- **v6+**（待定）：基于 ablation 结果，可能**移除** `struct` 和 `style` 族（ablation 显示去掉反而更好）

## 输入

- 训练集：`02_environment/data_registry/` 中 `human_poems` + `human_labels` 的**训练划分**
- 验证集：上述的**验证划分**（**测试集不可见**）
- 人工评价标签：固定不变
- **迭代期新增**：从失败模式中获得的反例样本（如 AI 垃圾负样本）

## 输出

- 每轮实验记录：`04_memory/experiment_logs/round_<NNN>.json`
- 失败样本：`04_memory/failures/round_<NNN>.jsonl`
- 阶段性最佳组合：每 5 轮 snapshot 到 `05_experiments/stage1_metric_search/best_snapshot.json`
- **版本化指标快照**：`05_experiments/stage2_hard_samples/round_<NNN>/frozen_metric.pkl`（Stage 2 用）

## 指标迭代闭环（v2.0 新增）

```
┌─────────────────────────────────────────────────────┐
│  1. 部署当前指标 (vN)                                 │
│  2. 在新数据上运行 → 找「高置信错误」                  │
│     (指标极确定但人类判断相反)                         │
│  3. 人工复核错误样本 → 判定「指标错 or 人类错」         │
│  4a. 指标错 → 提取失败模式 → 加特征 或 加反例训练样本   │
│  4b. 人类错 → 修正标注 → 重新评估                      │
│  5. 重训 (vN+1) → 在 OLD 数据 + NEW 数据上评估         │
│  6. 对比 vN vs vN+1 → 通过则发布 vN+1                  │
└─────────────────────────────────────────────────────┘
```

**触发条件（方案 §3.1「发现信号」映射）**：

| 发现信号 | 指标侧表现 | 动作 |
|---|---|---|
| 反例 | 指标高置信但人类反对 | 加入失败样本库 → 提取特征 |
| 异常 | 指标在某个 strat 上系统性失效 | 单独分析该 strat → 针对性加特征 |
| 稳定负结果 | 加了特征但 kappa 不变 | 放弃该方向，记录为负结果 |
| 失败模式 | 连续 3 轮无改善 | 回溯问题定义 / 特征空间 |

## 单轮步骤（v2.0 修订）

1. **观察**：读取上一轮一致性结果与失败样本摘要。
2. **边界检查**：调用 `check_agent/audit_cycle.md#pre_round`。
3. **动作**（v2.0 扩展）：
   - 调整特征组合
   - 调整特征权重
   - 调整聚合方式
   - **v2.0 新增**：加新特征族（如 purity、style）
   - **v2.0 新增**：加反例训练样本（需经人类复核确认）
   - 提出反例分析（不修改特征库）
4. **执行**：调用 `skills/SKILL_metric_eval.md` 计算新一致性。
5. **评估协议**（v2.0 新增）：
   - 固定 val split（`train_val_split(seed=42, val_ratio=0.2)`）保证可比
   - 指标：Accuracy / Quadratic Kappa / F1 / Brier / ECE
   - 跨数据集：原 val + 专家集 + AI 诗集（209 human-labeled）
6. **反馈**：
   - 性能反馈：与上一轮差值 vs. `0.01`
   - 失败反馈：识别指标判断与人类判断显著不一致的样本
7. **边界检查**：`check_agent/audit_cycle.md#post_round`。
8. **记录**：调用 `skills/SKILL_log_round.md`。

## 版本发布条件

- 在固定 val split 上 kappa 提升 ≥ 0.01
- **不**在跨数据集评估上退化（专家集、AI 诗集）
- 失败模式已被新特征或新反例处理
- Check-Agent 审计通过

## L2 子指标分析（v2.0 新增）

每个族独立训练一个 LR，输出「人类依赖哪些特征」报告。这直接回答方案 §1.3 的科学问题。

**已知结果（13 轮实验后）**：

| 族 | 单独 kappa | ablation Δkappa | 含义 |
|---|---|---|---|
| **form** | **0.948** | -0.008 | **最重要的单族**（行数 / 古典格式）|
| jump | 0.930 | -0.009 | 逻辑跳跃代理 |
| struct | 0.920 | **+0.018** | **去掉反而更好**——可能是噪声 |
| lang | 0.920 | 0.000 | 意象 / 文言（中性）|
| purity | 0.919 | -0.009 | 纯净度（仅对 AI 仿诗有用）|
| style | 0.911 | **+0.017** | **去掉反而更好**——v5 加了没效果 |
| music | 0.902 | 0.000 | 平仄（简化版中性）|
| baseline | 0.902 | — | 字符重叠 |

**结论**：
- `form` 是最关键的族
- `struct` 和 `style` 可能需要重新设计（ablation 显示负贡献）
- 后续 v6+ 可以考虑：精简特征库，只保留 `form + jump + lang + purity + music + baseline`
